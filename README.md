# StudyMate

A multi-page study planner built with HTML, CSS, browser JavaScript, Node.js, Express, and MongoDB.

## Pages and features

- Sign up and sign in with password hashes and server-side sessions.
- Dashboard with weekly class and task summaries.
- Weekly timetable with manual class entry, overlap checking, and deletion.
- Timetable image OCR that creates an editable draft for review before saving.
- Tasks with due dates, completion, deletion, and browser notification reminders.
- Focus timer and a distraction list with device Focus / Digital Wellbeing setup guidance.
- Per-account ownership checks for every saved planner entry.

## Run locally

Requires Node.js 20+ and a MongoDB database. Create a free MongoDB Atlas cluster or run MongoDB locally.

1. Copy `.env.example` to `.env` and set `MONGODB_URI` and a long random `SESSION_SECRET`.
2. Install packages with `npm install`.
3. Start the app with `npm run dev` for development or `npm start` normally.
4. Open `http://localhost:3000`.

The server serves the separate HTML pages from `public/` and exposes JSON endpoints under `/api`.

## Deploy globally

The app is a standard Node web service and can be hosted on Render, Railway, Fly.io, or another Node host. A Render Blueprint is included in `render.yaml`: connect the repository in Render and create the service from that Blueprint. Before it can start, provide `MONGODB_URI` when prompted. `SESSION_SECRET` is generated by Render and `NODE_ENV` is set to production. The service uses the host-provided `PORT` and serves on its public HTTPS URL. Never commit `.env` or paste database credentials into frontend files. In MongoDB Atlas, create a database user and allow access from your hosting service; Atlas requires an allowed network IP and database credentials for connections. See [Render Blueprint documentation](https://render.com/docs/blueprint-spec) and [MongoDB Atlas connection troubleshooting](https://www.mongodb.com/docs/atlas/troubleshoot-connection/).

## Product scope notes

OCR is best-effort and should always be checked by the user. Browser notifications in this version are scheduled by the open page, so the page must remain open and the browser must grant permission. A web page cannot block installed apps or other websites; users can use their device's built-in Focus or Digital Wellbeing controls. Reliable background alarms and system-wide app blocking require a native app or a separate push-notification service.
